# BagUI MCP

A [Model Context Protocol](https://modelcontextprotocol.io) server that lets AI assistants (Claude, Cursor, VS Code Copilot…) search, inspect and install [BagUI](https://bagui.pro) components.

## Tools

| Tool | Description |
| --- | --- |
| `list_categories` | Categories with their component counts |
| `list_components` | Components, filterable by `category` and `tier` (free/pro) |
| `search_components` | Keyword search (title, description, tags, category) |
| `get_component` | Metadata, dependencies, files, install command and, with `include_source`, the full source code |
| `get_install_command` | The install command for npm, pnpm, yarn or bun (returned, never executed) |

Resources: `bagui://registry` (all components) and `bagui://component/{slug}`.

## Setup

Build it once from the repository:

```bash
cd mcp
npm install
npm run build
```

Then register `node /absolute/path/to/bag-ui/mcp/dist/index.js` in your client.

**Claude Desktop** (`claude_desktop_config.json`) / **Cursor** (`.cursor/mcp.json`):

```json
{
  "mcpServers": {
    "bagui": {
      "command": "node",
      "args": ["/absolute/path/to/bag-ui/mcp/dist/index.js"]
    }
  }
}
```

**Claude Code:**

```bash
claude mcp add bagui -- node /absolute/path/to/bag-ui/mcp/dist/index.js
```

**VS Code** (`.vscode/mcp.json`):

```json
{
  "servers": {
    "bagui": { "type": "stdio", "command": "node", "args": ["/absolute/path/to/bag-ui/mcp/dist/index.js"] }
  }
}
```

Once published to npm, `"command": "npx", "args": ["-y", "bagui-mcp"]` works the same way.

## Configuration (environment variables)

| Variable | Description |
| --- | --- |
| `BAGUI_REGISTRY_PATH` | Local `registry.json` (highest priority) |
| `BAGUI_REGISTRY_URL` | HTTPS URL of a registry JSON (cached 12 h, falls back to the bundled snapshot when offline) |
| `BAGUI_REGISTRY_DIR` | Folder of built registry items (e.g. `public/r`) used to read component source code locally instead of fetching `https://bagui.pro/r/<slug>.json` |

Without any variable, the registry snapshot bundled at build time from the repository's `registry.json` is used.

## Design notes

- `registry.json` stays the single source of truth: `data/registry.json` is generated by `npm run sync-registry` and git-ignored.
- Registry parsing and install-command building are shared with the VS Code extension (`../vscode/src/utils`), so both stay consistent.
- Slugs are validated against a strict pattern before building any command.
